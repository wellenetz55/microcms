1. 仕組み
microCMSで新着情報・コラムを公開／更新／非公開化
 → WebhookでGitHub Actionsを起動
 → 公開中の記事を全件取得（100件ずつ。下書きキーは使いません）
 → 本文画像・アイキャッチ画像を取得して /assets/cms/ に保存
 → TOPのお知らせ、一覧、詳細、OGP、構造化データ、サイトマップを生成
 → 完成した一式をSSHでエックスサーバーへ転送
 → チェックサム検証後、公開ファイルを更新
閲覧時にはmicroCMSのAPIを使わず、画像もエックスサーバーから配信します。
公開後も静的HTMLが残るので、CMSの障害中も既存記事を表示できます。
公開反映は処理完了後です。処理待ち／画像数によって数分以上かかる場合があります。

2. microCMSの準備（2つともリスト形式API）
APIエンドポイント：news（新着情報）、column（コラム）
同じフィールド構成を使います。

フィールドID       種類                  必須
 title            テキストフィールド    はい
 body             リッチエディタ        はい
 description      テキストエリア        いいえ（SEO・SNS向け説明文）
 cover            画像                  いいえ（アイキャッチ兼OGP）

公開日時はmicroCMS標準のpublishedAt、更新日時はrevisedAtを使用します。
URLは /news/コンテンツID/ または /column/コンテンツID/ です。
IDには半角英数字・ハイフン・アンダースコアを使用し、公開後は変更しないでください。
ID変更時はURLも変わります。自動301リダイレクトは未実装です。
description省略時は本文から短い説明文を生成します。
cover省略時は既存の共通OGP画像を使います。
画像はmicroCMSにアップロードしたPNG/JPEG/WebP/GIFに対応します。
外部画像の直貼り、SVG、iframe、スクリプト埋め込みは対応しません。
PDFや動画を使う場合はエックスサーバーに別途置き、本文からリンクしてください。
画像は1ファイル25MBまで。リッチエディタ内の色・サイズなどの任意スタイルは
サイト側のデザインに統一します。表・見出し・リスト・引用・リンクに対応します。
画像の代替テキスト（alt）は本文画像で設定してください。

APIキー
news/columnのGETを許可する読み取り専用キーを使います。
既存のdefaultキーがGETのみであることを確認済みです。
「下書きコンテンツの全取得」権限は有効にしないでください。
キーをHTML、公開リポジトリ、チャットへ貼らないでください。
プログラムはX-MICROCMS-API-KEYヘッダーで認証します。

そちらが優先される場合があります。公開前に実URLで表示を確認してください。

    次の実行から実際にエックスサーバーへ反映されます。

6. microCMSのWebhook
newsとcolumnのAPI設定 → Webhook → GitHub Actions
使用するリポジトリ所有者名、リポジトリ名、専用GitHubトークンを登録。
トリガーイベント名：microcms_build
トークンは対象リポジトリに限定したものを使い、必要権限は公式手順に従います。
トークンはmicroCMS設定欄にだけ登録し、チャットへ貼らないでください。

通知タイミング：
 ・公開・更新（管理画面／予約公開など、使う公開方法）
 ・公開終了／公開中記事を下書きに戻す（予約終了を使う場合はそれも）
 ・削除
下書き保存だけでは公開しません。WebhookにdraftKeyが含まれても使用しません。
Webhookを逃した場合はRun workflowで全件同期できます。
失敗通知はGitHubのActions通知設定を利用してください。

7. 既存記事をCMSへ移す場合
現在の既存記事はそのまま維持され、新しいCMS記事を追加できます。
過去の記事はCMSへ自動登録していません。
同じURLで過去記事を移行する際は、同じコンテンツIDで本文を登録し、
cms/config.jsonのlegacy_overridesへ該当URLを追加してください。
例：config.jsonのservice_domainはそのまま残し、legacy_overridesの配列へ
 "/news/example/" を追加。
移行後はこの設定を残します。CMSで非公開にした時に旧記事が復活しないためです。
同じURLが衝突し、legacy_overridesにない場合は配信を停止します。

8. 失敗時と非公開化
記事取得・画像取得・ページ生成・チェックサム検証の失敗時は配信しません。
以前に配信したCMS記事のうち、今回公開されていない記事のindex.htmlを削除します。
空になった記事ディレクトリは削除しますが、それ以外のファイルは削除しません。
配信先の.htaccess、手動設置PDF、フォーム等は一括削除しません。
同じパスのサイト生成ファイルは上書きします。
画像は削除済み記事でも他の箇所から参照される可能性があるため自動削除しません。

更新前のファイルはpublic_htmlの外にある
 .wellenetz-cms-public_html/backups/<ID>/
へ保存します（公開先がプレビュー用なら末尾はそのフォルダ名）。
書き込み中の通常のエラーは自動復元します。
プロセス強制停止などでpending.jsonが残った場合、次の配信を止めます。
管理者が次のコマンドで復元してから再実行してください。
 python3 cms/publish.py --release <生成物フォルダ> --root <公開先> --state <状態保存先> --rollback
※この復元操作では--releaseは必須引数ですが内容は参照しません。

バックアップは自動削除しません。管理者が容量を確認し、必要な世代を保管。
更新はファイル単位の置き換えです。全ページが完全に同時に切り替わる構成ではありません。
完了済み配信の差し戻しは、以前のArtifactを同じdeploy.pyで再配信します。
復元・差し戻しでも現在のCMSの記事との整合性を確認してください。
