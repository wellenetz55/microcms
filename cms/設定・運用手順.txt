ベレネッツ：microCMS → GitHubで生成 → エックスサーバーがHTTPS取得
更新日：2026-10-07

■ 現在の構成
microCMS：wellenetz.microcms.io
GitHub：https://github.com/wellenetz55/microcms（公開リポジトリ）
公開先：https://www.wellenetz.co.jp/
公開フォルダ：/home/order/wellenetz.co.jp/public_html
取得プログラム：/home/order/.wellenetz-cms-pull/（権限700、公開フォルダ外）
サーバーのSSH国外アクセス制限：ON。自動更新ではSSH接続を使いません。
サーバー標準Python 3.6.8で、取得・検証・反映・復旧の専用テスト10件が成功しました。
GitHub側はPython 3.12で記事取得・サイト生成・全19件のテストを行います。

■ 有効化状況
GitHub：CMS_RELEASE_ENABLED=true。公開用ZIPの生成・Releases保存を有効化済み。
サーバー：config.jsonのenabled=false。本番への適用は無効です。
サーバーCron：取得検証後にOFFへ停止済み。本番Cronはまだ有効にしません。
microCMS：news/columnを作成済み、公開記事は0件（初回確認時）。Webhookは未設定。
本番ファイルの初回反映・Webhook有効化には、生成物と更新対象の確認が必要です。
サーバーのPython更新や国外アクセス制限の解除は不要です。

■ 仕組み
1. microCMSで新着情報・コラムを公開／更新／非公開化。
2. WebhookからGitHub Actions「Build microCMS for Xserver pull」を起動。
3. 公開中の記事を取得し、本文画像・アイキャッチをダウンロードして静的HTMLを生成。
4. テスト・ハッシュ検証が成功した公開用ファイルだけをwellenetz-site.zipにまとめる。
5. GitHub Releasesへ下書きとしてZIPをアップロードし、完了後に公開する。
6. エックスサーバーのCronが5分間隔で最新リリースをHTTPS取得。
7. 取得元・GitHubのSHA-256・各ファイルのSHA-256・パスを検証し、公開ファイルを更新。
閲覧時にmicroCMS APIは使いません。画像もエックスサーバーから配信します。
反映時間はGitHubのビルド時間＋次のCronまで最大5分＋取得・反映時間です。

■ 取得元と権限
取得元はwellenetz55/microcmsの正式リリースに固定しています。
タグ形式：cms-production-<GitHub実行ID>-<試行番号>
公開Releasesの取得にGitHubトークンは不要です。サーバーにはGitHub秘密情報を置きません。
通信は証明書検証を有効にしたHTTPSのみ。GitHubのAPI・本体・正式配布先だけを許可します。
GitHub APIが返すasset digest（sha256）と実データのハッシュを照合します。
これはGitHubのリポジトリ権限とTLSを信頼する方式で、独立した電子署名ではありません。
このためGitHubの書き込み権限とアカウント認証を適切に管理してください。
ZIPに含まれるのは公開用HTML・画像等のみです。Pythonや設定ファイルをZIPから実行しません。
サーバー用プログラムの更新は管理者がファイルマネージャ等から行います。

GitHub Repository Secret：
 MICROCMS_API_KEY（news/columnのGET専用。下書き全取得や書き込み権限は不要）
GitHub Repository Variables：
 MICROCMS_SERVICE_DOMAIN：省略時wellenetz
 CMS_RELEASE_ENABLED：trueで公開用ZIPをReleasesへ保存
旧SSH方式のSecrets・Variablesは現在の配信処理では使用しません。
既存の診断用SSHワークフローは履歴用に残っています。通常運用では実行しません。
旧CMS_DEPLOY_ENABLED=falseは残っていますが、新方式の制御には使いません。
書き込み権限contents:writeは、GitHubのreleaseジョブにだけ設定しています。

■ microCMSの記事入力
API：news（新着情報）／column（コラム）。いずれもリスト形式。
 title：テキスト、必須
 body：リッチエディタ、必須
 description：テキストエリア、任意（SEO・SNS説明文）
 cover：画像、任意（アイキャッチ・OGP）
URLは /news/コンテンツID/ または /column/コンテンツID/。
IDは半角英数字・ハイフン・アンダースコア。公開後に変えるとURLも変わります。
公開日時・更新日時はmicroCMS標準項目を利用します。
画像はmicroCMSへ登録したPNG/JPEG/WebP/GIF、1ファイル25MBまでです。
外部画像直貼り、SVG、iframe、スクリプト埋め込みは取り込みません。
PDF・動画は別途サーバーへ設置してリンクします。
CMS本文の任意の色・サイズはサイトの共通デザインに統一します。

■ GitHubで手動生成する
Actions → Build microCMS for Xserver pull → Run workflow
 source=sample：サンプル検証のみ。noindexで、Releasesには保存しません。
 source=published：microCMSの公開記事を取得。CMS_RELEASE_ENABLED=trueならRelease作成。
実行が失敗した場合、新しい完全なリリースは公開しません。既存サイトは維持されます。
Artifactsのwellenetz-productionは従来どおり手動ダウンロードにも利用できます。
公開リポジトリなので、ReleaseのZIPは誰でも取得可能です。公開用ファイルだけを入れます。

■ エックスサーバーへの設置
公開フォルダ外の/home/order/.wellenetz-cms-pull/へ次を設置します：
 pull.py、publish.py、config.json
検証用：package_release.py、test_pull.py、verify_server.py
config.jsonはcms/pull-config.example.jsonをコピーして使い、初期値enabled=falseを維持します。
フォルダ権限700。ログ・状態・バックアップも公開フォルダ外に保存します。

本番を変更しない確認コマンド：
 /usr/bin/python3 -B /home/order/.wellenetz-cms-pull/pull.py --config /home/order/.wellenetz-cms-pull/config.json

有効化後の本番コマンド（config.jsonのenabled=trueが別途必要）：
 /usr/bin/python3 -B /home/order/.wellenetz-cms-pull/pull.py --config /home/order/.wellenetz-cms-pull/config.json --apply > /home/order/.wellenetz-cms-pull/update.log 2>&1
Cronの「分」=*/5、「時・日・月・曜日」=*。設定状況ON。
--applyとenabled=trueの両方がそろうまで本番ファイルは更新しません。

■ 初回公開前の確認
1. 最新の生成物をプレビューして、既存本番サイトとの差分を確認。
2. サーバー全体のバックアップを管理者が取得。
3. dry runで変更・削除件数を確認。既存の.htaccessやPHP優先表示にも注意。
4. 公開承認後にenabled=trueと--applyのCronを有効化。
5. 公開URLで新着情報・コラム・画像・フォーム・サイトマップを確認。
6. microCMS Webhookを設定し、実際の記事公開からの一連の更新を確認。

■ Webhook（未設定）
newsとcolumnのAPI設定 → Webhook → GitHub Actions。
リポジトリ所有者wellenetz55、リポジトリmicrocms、イベント名microcms_build。
対象リポジトリに限定した専用GitHubトークンを使用し、必要権限は公式手順に従います。
新しいトークンの発行・入力はユーザー自身が行います。チャットや公開コードには貼りません。
公開・更新・公開終了・公開中記事を下書きに戻す・削除を通知対象にします。
下書き保存では公開しません。Webhook内のdraftKeyは使用しません。
Webhook未設定でも、Run workflowの手動実行は可能です。

■ 既存記事・失敗・復旧
既存記事をCMSへ移す場合は同じIDを使い、cms/config.jsonのlegacy_overridesへURLを追加。
指定なしで既存URLと衝突した場合は生成を停止します。
CMSで非公開にした記事は、前回管理対象になっていた記事だけ削除します。
手動PDF・.htaccessなど管理対象外のファイルは一括削除しません。
共有画像は自動削除しません。公開用ファイルは同一パスにあるものを上書きします。
取得・検証失敗時は本番へ適用せず、公開済みサイトを維持します。
二重実行はロックで防止します。適用済みReleaseは再ダウンロードしません。
適用済みReleaseの改変や、それより古いReleaseへの自動巻き戻しを拒否します。
各ファイルは一時ファイルから置換。全サイト一括での原子的切替ではありません。
バックアップはstate/publisher/backups/、途中更新の記録はstate/publisher/pending.jsonです。
中断を検出した場合は自動再開せず停止します。管理者がpublish.pyの--rollbackで復旧します。
停止する場合はCronをOFFにし、config.jsonをenabled=falseへ戻します。
