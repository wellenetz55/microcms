WELLENETZ — Multi-page redesign
作成日: 2026-10-02

1. サイトを表示する
このフォルダーで次を実行（GitHubから取得した場合は先にHTMLを生成）:
  python3 build.py
  python3 -m http.server 8000 --bind 127.0.0.1 --directory dist
ブラウザーで http://127.0.0.1:8000/ を開いてください。
URLはサイトのルートからの絶対パスを使っています。HTMLのダブルクリックではなく、上記のローカルサーバーで閲覧してください。

2. 同梱物
  dist/                  プレビュー用サイト（検索除外・計測なし）
  dist-production/       本番公開用サイト（--productionで生成）

  marketing_pages.py     マーケティング事業・配下3ページのデザインと本文

  DESIGN-SUMMARY.txt     構成とデザイン仕様

3. 更新方法
共通レイアウトと主要ページは build.py、ブランディング事業トップとAI詳細は branding_pages.py、マーケティング関連4ページは marketing_pages.py、その他の下層本文は src/source-pages.json、事例は src/cases.json を編集。
  python3 build.py
共通スタイル: dist/assets/site.css
共通動作: dist/assets/site.js
サイトはフレームワーク不要。本番公開時は python3 build.py --production を実行し、
dist-production/ の中身を静的Webサーバーの公開ルートに置いてください。
公開用ZIP「ベレネッツ_本番公開用.zip」は、この中身を収録しています。

5. お問い合わせ
総合・メディア・講師依頼・協業提携の4フォームを、それぞれ専用のform.runへ接続しています。
入力 → 確認 → 送信の2段階操作です。必須項目・メール形式を検証し、確認画面から修正できます。
form.runへ通常のHTTPS POSTで送信します。送信完了・サーバー側エラーの表示はform.runが行います。
JavaScript無効時はブラウザーの入力検証後、そのまま送信します。
ブラウザーストレージには入力内容を保存しません。送信後のデータはform.run側で扱われます。
各ページの問い合わせ種別・送信先は contact_form.py の FORMS で管理します。
接続内容と本番前確認は「お問い合わせフォーム-設定と確認.txt」を参照してください。

プレビュー用distは検索エンジンに掲載しない設定です。正式公開には python3 build.py --production で作るdist-productionを使用してください。

【2026-10-07 CMS連携：サーバー側HTTPS取得方式】
新着情報・コラムをmicroCMSから静的HTMLと画像へ生成します。
GitHub Actionsで生成・検証した公開用ZIPをReleasesへ保存し、エックスサーバーがHTTPSで取得します。
サーバーへの国外SSH接続は不要です。国外アクセス制限はONを維持しています。
サーバー標準Python 3.6.8で専用10テストが成功。GitHub/ローカルの全19テストも成功。
実際の公開用ZIPの取得・検証・ドライランまで成功しました。
本番反映時の変更予定は102ファイル、CMS記事削除0件。本番ファイルはまだ変更していません。
サーバーのenabled=false、Cron=OFF。本番反映とmicroCMS Webhookは未有効化です。
設定手順：cms/設定・運用手順.txt
実行：python3 cms/pipeline.py --fixture --output .cms-output/demo
従来のpython3 build.pyは既存記事だけを生成します。CMSの更新にはcms/pipeline.pyを使います。
CMS運用開始後は従来のbuild.pyだけで本番を上書きしないでください。
